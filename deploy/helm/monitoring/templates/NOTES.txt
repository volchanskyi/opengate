opengate-monitoring ({{ .Release.Name }}) deployed to namespace {{ .Release.Namespace }}.

Out-of-band objects this chart references (create BEFORE / alongside install):

  1. Secret with Grafana + Telegram + Postgres credentials:
       kubectl -n {{ .Release.Namespace }} create secret generic {{ .Values.existingSecret }} \
         --from-literal=GF_SECURITY_ADMIN_PASSWORD=... \
         --from-literal=POSTGRES_PASSWORD=... \
         --from-literal=TELEGRAM_BOT_TOKEN=... \
         --from-literal=TELEGRAM_CHAT_ID=...

  2. Grafana dashboards + alerting ConfigMaps, and the scrape configuration.
     These are rendered from the canonical files and read back, rather than
     created by hand — an apply nobody re-ran is how the cluster came to hold
     seven of thirteen alert rules and none of the per-container series:

       TELEGRAM_CHAT_ID=... NAMESPACE={{ .Release.Namespace }} \
         deploy/scripts/monitoring-config-apply.sh

     The nightly infrastructure-drift workflow runs the same script, so what the
     cluster holds is compared with what the repository declares every night.

    promtail.runAsRoot=true.
  - Grafana dashboards render and datasources resolve the in-cluster Services.
  - Keep application log queries pointed at the in-cluster Loki Service.
