# Workflow identity submodule

The GitHub workflows' own cloud login:

- an IAM **group** and **user**, both named `opengate-workflows`, the user a member of that group
  alone and of no administrators group;
- one **policy**, letting the group fetch a kubeconfig for the OKE cluster (`use clusters`).

Everything the login may do inside the cluster comes from Kubernetes RBAC in
[`deploy/cluster/workflow-access.yaml`](../../../cluster/workflow-access.yaml), which the
approval-gated cluster job applies. The login cannot read the master key's secret or list any
secret ([ADR-128](../../../../docs/adr/ADR-128-machine-identity-lifecycle.md)).

The user's API key is generated by an administrator and stored as GitHub secrets; Terraform holds
no key material. The `workflow_user_id` output is the `OCI_WORKFLOW_USER_OCID` secret.
